# PlantScope 后端性能与稳定性报告

日期：2026-10-11

## 测试方法

- 从本地正式库克隆出隔离测试库执行集成与 HTTP 测量；未向正式库写测试数据。
- 数据库：MySQL 8.0.44，150 株公开植物。应用：Tomcat 10.1.60 Embedded、Java 21 运行 Java 17 编译产物。
- HTTP 每条路径预热 5 次，再顺序测量 30 次；报告 p50 / p95 毫秒。基线与优化后使用同一机器和克隆数据。优化后为避免跨路径共享每分钟限额，每条路径单独启动 Embedded Tomcat。启动时间不计入采样。
- 并发检查为 4 个客户端线程、每线程 20 次描述查询；共 80 次，低于每分钟限额。
- 结果是本地小数据集下的响应时间样本，不代表生产网络或未来大数据量，不据此宣称普遍性能提升。

## HTTP 响应对比

| 路径 | 基线 p50 / p95 | 优化后 p50 / p95 | HTTP 状态 |
|---|---:|---:|---|
| 首页 | 24 / 29 ms | 26 / 29 ms | 全部 200 |
| 名称建议 | 4 / 4 ms | 4 / 5 ms | 全部 200 |
| 学名/名称检索 | 13 / 14 ms | 16 / 20 ms | 全部 200 |
| 智能外观描述 | 20 / 22 ms | 17 / 23 ms | 全部 200 |
| 外观筛选页 | 15 / 17 ms | 18 / 26 ms | 全部 200 |
| 基础检索 | 9 / 10 ms | 11 / 13 ms | 全部 200 |

简单路径的差异落在少数毫秒，波动没有证明普遍加速。智能描述的 p50 低 3ms、p95 高 1ms；名称、外观筛选和基础查询样本略慢。更明确的改进是：明显外观描述不再多跑名称 `COUNT` 与结果 SQL（单请求从 6 条降为 4 条）。状态核验增加了处理工作，不能据这些样本宣称所有查询变快。

| 并发样本 | 基线 | 优化后 |
|---|---:|---:|
| 4 线程、80 次描述检索 | 全部 200；p50 35ms、p95 64ms | 全部 200；p50 25ms、p95 41ms |

该并发样本只用于发现回归；单次本机测试不足以支撑容量或吞吐量结论。

## 单请求 SQL 数量（按实际 DAO 调用路径核对）

| 路径 | 基线 SQL 数 | 优化后 SQL 数 | 说明 |
|---|---:|---:|---|
| 名称建议 | 1 | 1 | 一条限量查询 |
| `/discover?mode=name` | 3 | 3 | 特征目录 1 条，名称总数与分页数据各 1 条 |
| 智能外观描述（无匹配候选） | 6 | 4 | 目录 1 条、名称总数与数据 2 条、特征解析与搜索 3 条；优化后跳过名称两条 SQL |
| 外观筛选（无候选） | 4 | 4 | 目录、特征解析、总数、候选页；有候选时另有一条批量解释查询 |
| 基础/专业分页检索 | 2 | 2 | 总数及当前页；连接不另行查询 |

以上计数基于 DAO 源码中的 JDBC 执行点，不是运行时 SQL 拦截器计数。搜索页每页固定 12 条，查询结果限制 50 条；特征查询最多 18 个条件。

## 数据库计划与索引

- `EXPLAIN ANALYZE` 的公开外观特征存在性查询使用已有覆盖索引 `idx_trait_value_search (trait_id, option_id, verification_status, plant_id)`；测试查询实际执行约 0.0365ms。正式库确认特征为 0，所以这不是有大量行时的容量测试。
- 化学组分查询计划显示扫描 `fatty_acid_components`，但该表正式核验记录当前为 0 行；含油率采样记录 88 条。`plant_oil_samples` 的植物关联索引、组分的 `sample_id` 唯一索引和组分名称索引均已存在。前导 `%` 的组分子串匹配不利用 B-tree；当前数据规模和执行计划没有证明增加全文搜索或额外索引有收益。
- 本轮没有修改数据库结构、没有新增索引，也没有对正式数据执行写入。

## 可靠性与安全检查

- 服务端搜索限流：名称建议每来源 IP 每分钟 60 次；搜索入口共享每来源 IP 每分钟 120 次的 JVM 内限流，限流返回 HTTP 429 / `RATE_LIMITED`。
- 请求日志在 requestId 下记录超过 500ms 的请求和服务异常；数据库错误对用户返回可重试提示，不显示 SQL 或堆栈。
- 参数使用白名单、数值范围校验、长度上限和 `PreparedStatement`；模糊输入中的 SQL 通配符现在作为普通字符处理。
- HikariCP 仍沿用项目现有配置，没有以当前数据规模为依据调整最大连接数或缓存。

## 验收结果

- `mvn clean test`：59 项测试，0 失败、0 错误；其中 13 项 MySQL 集成测试在此命令下按项目默认配置跳过。
- `mvn package`：成功，生成 `target/oil-plants-knowledge.war`。
- `./scripts/integration-test.sh`：使用隔离克隆库，13 项 MySQL 集成测试全部通过。
- `./scripts/business-flow-test.sh`：Embedded Tomcat 业务端到端测试通过，覆盖公开检索、建议、外观筛选状态、认证/权限、CRUD、搜索限流等路径。特征成功案例使用隔离库中的临时夹具，只验证数据库流转和状态逻辑，不代表正式知识库已有可检索外观数据。
- `./scripts/compile-jsps.sh`：JSP 编译 0 错误；`node --check src/main/webapp/assets/js/app.js` 与 `git diff --check` 通过。
- 只读正式库计数仍为 150 株公开植物、0 条已确认外观特征、88 条已核验含油率样本、0 条已确认脂肪酸组分；正式数据库未写入测试夹具。

## 限制

没有对每条 JDBC 语句做应用内运行时毫秒计时；采用了 DAO 调用数审查、MySQL `EXPLAIN ANALYZE` 和端到端 HTTP 测量。测试没有验证真实 SMTP、生产反向代理、多实例限流或生产负载。
