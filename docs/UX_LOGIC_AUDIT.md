# PlantScope 用户体验逻辑审计

审计日期：2026-10-11。检查对象为当前 JSP/Servlet/JDBC 工程、`nonfood_oil_plants` 本地 MySQL 数据和本轮实际 HTTP/Tomcat 测试。范围只覆盖用户体验逻辑与数据可用性；没有新增产品页面、Servlet、Service、表或迁移，也没有改动原课程 PDF 与已核验课程数据。

## 用户角色与主要页面

| 用户 | 主要路径 | 访问边界 |
|---|---|---|
| 游客 | 首页 `/`、名称/描述 `/discover`、外观 `/find-by-traits`、名录 `/plants`、分类 `/categories`、详情 `/plant?id=…` | 无需注册即可浏览公开记录；缺少可信外观证据时明确显示证据不足 |
| 注册用户 | `/favorites`、`/history`、`/profile`、`/compare`、`/search/advanced` | Session 与现有 `AuthFilter` 控制需要登录的路径；查询条件可随登录保留 |
| 管理员 | `/admin/*` | 由现有角色过滤器限制；普通用户对管理员审核与维护路由返回拒绝 |

## 发现的问题与处理

| 严重度 | 实际问题及证据 | 本轮处理 | 当前状态 |
|---|---|---|---|
| P0 | 数据库中没有一条 `CONFIRMED` 外观特征，外观搜索不能为真实植物给出可信候选；候选数据不能冒充正式知识 | 保留原外观检索能力；空结果写明原因、未知值与待核值不作为匹配；不批准机器候选 | 数据层阻塞仍在，真实外观识别目标未达成 |
| P1 | `/discover` 曾通过通用全文查询判断是否名称命中，植物描述或形态文本可能被误当成名称结果 | 改用 `PlantDao.searchByName` 做名称专用查找；名称判断不再搜描述字段；公开查询和建议不采用未核验别名 | 已修复并通过集成/E2E |
| P1 | 登录拦截没有完整保留查询字符串，登录后可能丢失高级筛选条件 | `AuthFilter` 保存受长度限制的路径及查询；`LoginServlet` 校验站内 `next`，避免开放重定向 | 已验证登录后回到原高级查询 |
| P1 | 游客从详情收藏时登录后容易离开原任务，收藏成功与否缺少反馈 | 详情显示返回该植物的登录入口；登录后明确显示“继续收藏”；收藏增删后有成功提示 | 已通过 E2E 验证 |
| P1 | 自然语言同时出现同一特征的互斥描述时，旧逻辑只保留先遇到的值 | `DescriptionParser` 标记同字段冲突；Servlet 停止自动匹配并要求修改条件 | 冲突输入 E2E 已覆盖 |
| P1 | 正式特征为零时，描述检索可能被页面或报告误读为“识别成功” | 页面区分解析、匹配和证据状态；无确认事实时显示“不足以可靠判断”；不生成虚构分数或候选 | 空证据路径已验证；无成功识别案例 |
| P2 | 详情页使用原始状态码、缺失值语义含糊，关联来源不易查看 | 显示面向用户的状态文字、关联来源与可用引用；采样记录、含油率、组分分开显示；缺失不显示为 0 | JSP 编译与 E2E 通过 |
| P2 | 117 条新增植物记录以拉丁学名作为中文名回退，页面可能让普通用户误以为这是中文名 | 名录、分类、对比、收藏、首页与详情标注“中文名待核”；重复拉丁名不再显示两遍 | 已修复；真实中文名仍需核验 |
| P2 | 共享特征选择 JSP 片段未声明 UTF-8，浏览器中“跳过/否定”文字乱码 | 给既有 `trait-selectors.jspf` 增加页面编码声明 | Jasper 零错误；浏览器预览确认文字正常 |
| P2 | 测试克隆库带有 45 条图片引用，但克隆的上传目录没有实际文件，浏览器不能据此确认存量图片显示 | E2E 继续校验新上传文件的格式、写入和读取；报告标注克隆存量图片显示未验证 | 新上传链路通过；存量图片文件显示未验证 |

## 对重复实现的处理

- 用现有 `PlantDao` 与 `PlantQuery` 完成名称和通用全文查询边界划分，没有新增 DAO、Service 或检索入口。
- `TraitDao` 将特征详情读取改为共用同一查询片段和映射函数，避免详情查询重复字段映射。
- 复用现有 `plant_knowledge_sources`、特征 DAO、Session、FlashFilter、收藏表和页面模板。没有新增表或管理页面。
- 没有删除文件或历史功能。实际移除的是错误的“描述全文命中即名称命中”分支、公开使用未核验别名的路径，以及向用户暴露原始状态码的显示方式。

## 仍需处理的问题

1. 当前 1,180 条特征值均为 `EXTRACTED`；要让真实外观检索工作，需要人工逐项按来源证据审核，不应批量批准。
2. 植物记录没有中文名称字段级核验状态；无法从现有结构统计“已确认中文名”数量。需核查现有 33 条非拉丁显示值，另有 117 条是拉丁学名回退。
3. 正式脂肪酸组成仍为 0 条。97 条候选须按原 PDF 表头、单位、样本和证据核验。
4. 本轮浏览器检查覆盖桌面实际数据库名称搜索与 375px 移动布局；未覆盖 768/1024/1440px 视觉矩阵、屏幕阅读器、真实 SMTP、压力测试和真实存量图片目录。

**结论：**核心页面流程已稳定到适合进入下一阶段视觉优化；但知识内容还不足以支持普通用户凭外观找到真实植物。产品可用性不能据页面可打开或解析器运行宣称达标。

## 搜索框交互专项复核（2026-10-11）

复用关系维持不变：首页、`/discover` 与 `/find-by-traits` 使用同一搜索 JSP 片段；名称、规则解析、特征查询和建议继续调用原 DAO、Service 与 Servlet，没有另建并行搜索实现。

本次浏览器复核发现两项体验缺陷并已修复：

- 描述示例首次点击不填入输入框。浏览器仍使用同一静态资源版本号，服务器静态资源缓存为一小时；脚本变更后旧版 JS 继续被使用。更新 `app.js`/`site.css` 资源版本号后，示例会填入文本并聚焦，不会自动提交。
- 用户切换搜索模式、编辑文本或更改特征时，页面仍显示上次查询结果。现在旧结果会隐藏，并显示“你已更改搜索方式或筛选条件；重新提交后查看更新结果”，防止把旧结果误认为新查询结果。

此外，描述“树上长着松塔，叶子像针”时，解析器先识别了针形叶，却仍将“叶、叶子”显示为未识别词语。解析器现在会将已识别特征的上下文词视为已解释，不再产生这类误报；仍未识别的原文继续保留。该描述只映射为乔木、针形叶和球果线索，并明确提示不能据此推断植物属种。

浏览器还暴露了 `fruit_shape` 特征标签乱码。备份正式本地库并在隔离库验证恢复后，新增 `database/migrations/20261016_fix_fruit_shape_label.sql`，只将该特征的显示标签修复为“果实形状”。正式库植物数仍为 150；没有改植物记录、特征证据、审核状态、原课程数据或审核历史。备份为 `tmp/backups/plant_scope_pre_fruit_shape_label_fix_20261011.sql.gz`，gzip 检查通过，且成功恢复到临时验证库核对 150 株和 20 项特征后删除验证库。

**数据边界：**真实公开库仍有 150 株；已确认外观特征为 0。故本轮浏览器实测的是名称检索、建议与条件交互。外观描述可解析，但因没有正式核验的特征记录，正确结果仍是证据不足，没有真实外观识别成功案例。

## 统一搜索体验追补（2026-10-11）

本次在上述基线之上整理入口，没有另建搜索 Servlet、Service、DAO 或数据库表。首页与 `/discover` 共用 `WEB-INF/views/common/unified-search.jspf`；名称、自然语言和外观查询仍走既有 `PlantDao`、`DescriptionParser` 与 `TraitService`，专业查询入口继续指向原 `/search/advanced`。

- 智能模式先识别数据库中的精确名称/学名/已核验别名，再决定名称或特征路径；用户手动选名称或外观模式时尊重该选择。无法解析的输入保留并允许继续改模式。
- 搜索建议使用真实数据库名称、学名和已核验别名；增加防抖、请求取消、过期响应保护以及方向键、Enter、Esc 操作。建议失败不阻止手动提交。
- 新手外观入口按实际特征词表显示“像扇子”等通俗选项及已确认记录覆盖数；补充特征可以展开，条件可清除，解析结果可逐项移除。
- `DiscoverServlet` 区分名称无结果、未识别描述、无已核验证据和服务失败。自然语言规则仅展示为特征提取，不称作 AI 或识别概率。
- 清理已无对应 JSP 控件的旧搜索 CSS（`home-search-modes`、`description-search-form`、`manual-correction`、`description-form-foot`、`discover-shortcuts`）；保留当前特征选择、候选卡片与详情样式。
- 修复现存特征词表中的显示标签编码，新增非破坏性迁移 `20261015_fix_trait_labels.sql`。它只更新分类/特征/选项中文标签并记录迁移，不更改植物、特征证据、审核状态或历史审核事件；已在本地库应用。

以本地 `nonfood_oil_plants` 数据库复核：150 条公开植物、117 条植物状态为 `VERIFIED`；已确认外观值 0，含油率已核验非空记录 88，已核验脂肪酸组分 0。因此实际完成的检索案例是名称/学名查询与数据库驱动的学名建议；外观描述可以解析和编辑，但还不能给出真实且已确认的植物候选。**外观检索的真实知识可用性目标仍未达成。**
