## 端到端覆盖

- 游客访问首页；游客访问 `/favorites`、`/admin` 被重定向登录。
- 通过 HTTP 注册临时账户并登录，确认个人中心可访问；普通用户访问管理区得到 403。
- 在数据库中把该临时账户提升为管理员后，请求立即按数据库角色刷新并通过管理区权限检查；测试结束删除账户。
- 管理员创建植物和采样数据；合法多条件检索返回该植物；详情显示已核验含油率。
- 收藏新增/移除、采样数值与组分修改后重读数据库确认状态与数值一致、植物删除和关联图片文件删除。
- 含油率 `101` 被服务端拒绝且没有写入数据库；无效图片签名不产生图片记录；合法临时 PNG 可保存并通过图片 Servlet 读取。
- 非数字植物 ID 返回 404 错误页；退出后受保护收藏路径再次要求登录。

端到端测试中的管理员角色提升只用于验证权限链路，不代表已初始化正式管理员。正式管理员初始化使用 `AdminBootstrap` CLI；本轮没有创建持久管理员账户。

## 搜索及数值验证

- `PlantSearchIntegrationTest` 验证含油率和组分条件必须在同一采样记录中成立，避免一个样本的油率与另一个样本的脂肪酸被错误组合。
- 该测试还插入含油率和组分均较高但标为 `NEEDS_REVIEW` 的临时数据，确认这些数据不能满足已核验范围筛选或数字关键词查询。
- 管理录入现在分别保存采样记录状态、含油率状态、组分状态；含油率为空时不能设为已核验，缺失状态也不能与一个已填写数值同时提交。
- 缺失数值继续使用 SQL `NULL`；详情页面不把待核验值显示为确定的百分比。

## 浏览器与静态页面检查

- 当前 WAR 在 Chrome 中检查了首页和数据库植物详情页；页面实际显示 33 条植物、89 条采样记录、88 条已核验含油率、45 张图片，详情将含油率状态单独标出。
- 前一轮界面检查已在 1440、1024、768、375 像素视口检查响应式首页、检索和导航。本轮修改主要增加详情/管理表单的核验状态字段；当前版本未重新在四个尺寸逐页完整回归。
- JSP 编译确认了模板语法，但管理员分类维护、用户启停和所有空态/数据库异常页面没有逐项浏览器操作回归。

## 验收期间修复

1. 高级检索以前会把 `NEEDS_REVIEW` 的含油率和脂肪酸值纳入数值筛选。现在范围条件、数字关键词和含油率排序只读已核验测量；组分名和百分比筛选也要求组分已核验。
2. 管理端原先把采样记录的通用状态同时用于含油率和组分，不能表达“油率已核验、样本整体仍待复核”等情况。现在三种状态分别读写，详情不再将未核验值当作确定百分比呈现。
3. 加入 `BusinessFlowE2E` 和 `scripts/business-flow-test.sh`，补充真实 HTTP、Session、Filter、MySQL 写入、管理员 CRUD 与图片上传生命周期检查。

首次集成测试发现旧 CRUD 测试绕过了 `PlantService`，直接调用 DAO 时没有为临时组分设置核验状态；测试改为走管理业务使用的 Service 更新路径后，三个数据库集成用例均通过。端到端测试启动器显式加载 JDBC 驱动，避免 Tomcat WebApp 类加载器与测试宿主类加载器隔离造成的测试端连接问题。
